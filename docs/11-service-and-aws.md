# 1부. 서비스 기능

## 1-1. 무엇을 해결하는가

기존 책 검색은 **제목이나 저자를 이미 알고 있을 때만** 쓸 수 있습니다.
그런데 사람들이 책을 찾는 실제 상황은 이렇습니다.

> "요즘 좀 지쳤어요. 마음이 편해지는 소설 있을까요?"
> "반전이 강한 미스터리 찾아줘"
> "무료로 지금 바로 읽을 수 있는 고전"

제목을 모르는 상태에서 **기분·상황·조건으로** 책을 찾는 일은 검색창이 못 합니다.
BookBot 은 이 간극을 메웁니다.

## 1-2. 기능 일람

### 대화로 찾기

| 기능 | 어떻게 동작하는가 |
|---|---|
| 기분·주제 검색 | Hardcover 의 정서 무드 태그(`reflective`, `hopeful` 등)로 매칭 |
| 제목·저자 검색 | 6개 소스 동시 조회 후 ISBN 기준 병합 |
| 국내 도서 | 한글로 물으면 알라딘이 국내 신간·번역서를 채움 |
| 무료 전자책 | 저작권 만료 고전의 EPUB·TXT·웹 읽기 링크 |
| 특정 책 상세 | 페이지 수·시리즈·내용 주의사항 |
| 대화 맥락 유지 | "그 책 몇 페이지야?" 같은 후속 질문 |

### 결과 표시

책은 채팅 글이 아니라 **카드**로 나옵니다.

- 실제 표지 이미지 (없으면 제목 이니셜로 대체)
- 커뮤니티 평점 + 평가자 수 + 출처
- 정서 무드 태그 · 장르 · 시리즈 정보
- 내용 주의사항 (접힌 상태로, 원하면 펼쳐서)
- 무료 전문 다운로드 링크
- 외부 링크 5종 (알라딘 · Google Books · Open Library · Hardcover · Gutenberg)
- **여러 소스에서 확인된 책** 표시 — 신뢰도 신호

카드 데이터는 전부 API 원본이라 **LLM 이 지어낼 수 없습니다.**

### 사용자 도구

| 기능 | 특징 |
|---|---|
| 읽을 목록 | 로그인 없이 담기. 최대 200권. 브라우저에 저장 |
| 답변 평가 | 좋음 / 아쉬움. 운영자가 어떤 질문에서 실패했는지 확인 |
| 낮 · 밤 테마 | 선택을 기억 |
| 한국어 · 영어 | UI 전환. 답변은 질문한 언어를 따름 |
| 진행 표시 | "도서 검색 중 · 한국 소설" 처럼 실시간 |
| 중단 | 답변이 길어지면 멈추기 |
| 새 대화 | 맥락 초기화 (담은 책은 유지) |

### 접근성

- 스크린리더용 상태 알림 (`aria-live`) — 본문 전체를 읽지 않고 상태만
- 저장 버튼 `aria-pressed`
- 색만으로 상태를 구분하지 않음 (활성 표시에 밑줄 병용)
- 외부 링크에 "새 창에서 열림" 안내
- `prefers-reduced-motion` 존중
- 터치 기기에서 조작 영역 확대

# 2부. AWS 를 어떻게 활용했는가

## 2-1. 전체 구성

```
                          ┌─────────────────────────┐
   사용자 ────────────────►│      CloudFront         │
                          │  (WAF · TLS · 캐시)      │
                          └──────┬───────────┬───────┘
                        정적 파일 │           │ /api/*
                                 ▼           ▼
                     ┌───────────────┐  ┌──────────────────┐
                     │      S3       │  │  API Gateway     │
                     │ (완전 비공개)  │  │  HTTP API        │
                     └───────────────┘  └────────┬─────────┘
                                                 ▼
                                   ┌─────────────────────────┐
                                   │        Lambda           │
                                   │  Node 22 · arm64        │
                                   └──┬────────┬─────────┬───┘
                                      ▼        ▼         ▼
                              ┌──────────┐ ┌──────┐ ┌─────────┐
                              │ Bedrock  │ │ DDB  │ │   SSM   │
                              │ Claude   │ │      │ │ 비밀값   │
                              └──────────┘ └──────┘ └─────────┘
                                      │
                                      ▼  (Lambda 에서 외부 호출)
                          도서 API 5종 · CloudWatch · SNS · Budgets
```

## 2-2. 서비스별 활용

### Lambda — 애플리케이션 전체

| 항목 | 값 | 왜 |
|---|---|---|
| 런타임 | Node.js 22 | 최신 LTS. `fetch` 내장 |
| 아키텍처 | **arm64** | x86 보다 약 20% 저렴, 성능 동등 |
| 메모리 | 1024MB | 외부 API 5종 병렬 호출에 CPU 가 필요 |
| 타임아웃 | 90초 | LLM + 도구 반복 여유 |
| 핸들러 | `bufferedHandler` | API Gateway 는 응답 스트리밍을 쓰지 않음 |

**핸들러를 두 개 만든 것**이 특징입니다. 같은 로직을 스트리밍(`handler`)과
버퍼(`bufferedHandler`) 양쪽으로 노출해서, 오리진 방식을 바꿔도 코드를 고치지
않습니다. 프론트도 두 응답 형태를 모두 처리합니다.

### DynamoDB — 단일 테이블 4가지 용도

테이블 하나(`bookbot`)에 pk 접두사로 종류를 나눕니다.

| pk | 용도 | TTL | 이렇게 한 이유 |
|---|---|---|---|
| `SESSION#<uuid>` | 대화 히스토리 | 24시간 | 테이블 4개면 관리 지점도 4배 |
| `LOG#<날짜>` | 질문·답변·평가 | 90일 | 날짜가 pk 라 하루치를 한 번에 조회 |
| `CACHE#<도구>#<해시>` | 외부 API 응답 | 6시간 | 같은 검색 반복 시 API 쿼터 절약 |
| `RL#<IP>` | 레이트리밋 카운터 | 짧음 | 원자적 증가(`ADD`)로 경쟁 조건 없음 |

- 온디맨드 과금 — 트래픽 없으면 0원
- **TTL 로 자동 삭제** — 정리 배치가 필요 없고, 개인정보를 오래 들고 있지 않습니다
- 평가는 `UpdateItem` + `ConditionExpression` — 기존 질문·답변을 덮지 않고
  없는 기록에 빈 항목이 생기지도 않습니다

### Bedrock — LLM

| 항목 | 값 |
|---|---|
| 모델 | Claude Sonnet 4.6 (`us.anthropic.claude-sonnet-4-6`) |
| API | `ConverseStream` (스트리밍 + 도구 호출) |
| 추론 프로필 | Geo(US) — 리전 쿼터보다 여유 |

**API 키가 없습니다.** IAM 역할로 호출하므로 관리할 비밀값이 하나 줄어듭니다.
도구 호출(tool use)로 Claude 가 스스로 검색 도구를 고르고, 결과를 보고 필요하면
다시 호출합니다. 반복은 기본 4회(API Gateway 모드에서는 3회) + **18초 시간 예산**으로 제한합니다.

### S3 + CloudFront — 프론트 배포

- S3 버킷은 **퍼블릭 접근이 완전히 차단**되어 있고 CloudFront OAC 로만 읽힙니다
- 오리진 2개(S3 + API Gateway)를 한 배포에 묶어 **단일 도메인** → CORS 설정이 없습니다
- `index.html` 은 캐시 금지, 해시 붙은 asset 은 1년 캐시
- SPA 라우팅: 없는 경로도 `index.html` 200 으로 응답
- HTTP → HTTPS 자동 리다이렉트

### SSM Parameter Store — 비밀값

SecureString 5개를 `/bookbot/prod/*` 경로에 둡니다
(도서 API 키 4개 + 오리진 비밀 `ORIGIN_SECRET`).

IAM 정책이 **경로 와일드카드**이고 코드는 `GetParametersByPath` 로 한 번에 읽으므로,
**새 키를 추가할 때 IAM 을 고칠 필요가 없습니다.** 알라딘 키를 추가할 때 실제로
권한 변경 없이 동작했습니다. Secrets Manager 대신 이걸 쓴 이유는 회전이 필요 없고
비용이 0 이기 때문입니다.

### API Gateway — HTTP API

원래 Lambda 함수 URL 로 만들었지만, 이 계정은 Lambda Public Access Block 때문에
쓸 수 없었습니다. 게다가 **CloudFront OAC + 함수 URL 조합은 본문 있는 POST 를
지원하지 않습니다** (브라우저가 SigV4 서명을 해야 함). 그래서 HTTP API 로 전환했습니다.

`ANY /api/{proxy+}` catch-all 이라 **새 엔드포인트를 추가해도 라우트 설정이
필요 없습니다.** `/api/feedback` 을 추가할 때 인프라를 건드리지 않았습니다.

### IAM — 최소 권한

| 허용 | 리소스 |
|---|---|
| `bedrock:InvokeModel*` | 파운데이션 모델 · 추론 프로필 |
| `dynamodb:GetItem/PutItem/UpdateItem/Query` | 테이블 `bookbot` 하나 |
| `ssm:GetParameter*` | `/bookbot/prod/*` |
| `kms:Decrypt` | SSM 기본 키 |

`Scan` 도 `DeleteItem` 도 없습니다. 리전을 `*` 로 둔 것은 Bedrock 교차 리전 추론이
다른 리전으로 라우팅되기 때문이며, 계정 ID 와 리소스 이름으로는 여전히 좁혀져 있습니다.

### WAF · CloudWatch · SNS · Budgets — 안전장치

| 서비스 | 설정 |
|---|---|
| WAF (CLOUDFRONT scope) | IP당 5분 300회. `/api/chat` 스코프다운 규칙 |
| CloudWatch 알람 | Lambda 오류 · 스로틀 · 응답시간 60초 초과 · Bedrock 시간당 출력 토큰 20만 |
| SNS | 알람 → 이메일 |
| Budgets | 전체 $100/월 · Bedrock $50/월. 실제 50%·80%, 예측 100% |
| CloudWatch Logs | 구조화 JSON 로그 → Logs Insights 로 집계 |

## 2-3. 비용 설계

**쓰지 않으면 0원** 인 서비스만 골랐습니다.

| 서비스 | 과금 | 미사용 시 |
|---|---|---|
| Lambda | 호출당 | 0 |
| DynamoDB | 온디맨드 | 0 (저장분만) |
| Bedrock | 토큰당 | 0 |
| API Gateway | 요청당 | 0 |
| S3 · CloudFront | 저장·전송 | 거의 0 |
| WAF | **월 고정 $7** | 발생 |

고정비는 WAF 뿐입니다. 2주 소규모 공개 운영 기준 **약 $56 (7.8만원)**,
Haiku 로 바꾸면 **$22 (3.1만원)** 입니다.

토큰 비용을 줄인 실제 방법은 **이중 채널** 입니다 — 도서 데이터 61,780자를
LLM 에는 779자만 보냅니다(99% 절감). 이것 하나로 Bedrock 비용의 대부분이 사라집니다.

# 3부. 이 서비스의 특징

## 3-1. LLM 이 지어낼 수 없는 구조

일반적인 RAG 챗봇은 검색 결과를 프롬프트에 넣고 LLM 이 그것을 요약합니다.
이 과정에서 표지 URL·평점·페이지 수가 **그럴듯하게 조작**됩니다.

BookBot 은 데이터를 두 갈래로 나눕니다.

| 채널 | 내용 | 목적지 |
|---|---|---|
| 원본 | 표지 URL · 평점 · 무드 · 다운로드 링크 | 프론트 카드 |
| 압축 | 제목 · 저자 · 연도 | LLM |

LLM 은 **말을 쓰는 일**만 하고, **사실을 표시하는 일**은 카드가 합니다.
그래서 카드의 모든 값이 실제 API 응답이고, 환각이 구조적으로 불가능합니다.

## 3-2. 6개 소스를 하나로 합치는 병합 엔진

각 API 는 가진 것과 없는 것이 정확히 갈립니다.

| | Google Books | Open Library | Gutendex | Hardcover | 알라딘 |
|---|---|---|---|---|---|
| 커버리지 | ★★★★★ | ★★★★☆ | ★★☆☆☆ | ★★★☆☆ | ★★★☆☆ |
| 한국 도서 | ★★★★☆ | ★★☆☆☆ | ✗ | ★☆☆☆☆ | **★★★★★** |
| 무드 태그 | ✗ | ✗ | ✗ | **★★★★★** | ✗ |
| 무료 전문 | △ | ★★★☆☆ | **★★★★★** | ✗ | ✗ |
| 국내 구매 | ✗ | ✗ | ✗ | ✗ | **★★★★★** |

ISBN-13 으로 조인하고, **필드별로 어느 소스를 믿을지 따로** 정합니다.
표지는 Google Books, 무드는 Hardcover, 국내서 표지는 알라딘, 무료 전문은 Gutendex.

한 소스가 죽어도 나머지로 답이 나갑니다(`Promise.allSettled`).
Gutendex 는 실제로 불안정해서 Open Library 폴백을 준비해 두었습니다.

## 3-3. 실패를 전제로 만든 구조

| 실패 | 대응 |
|---|---|
| 도서 API 하나가 죽음 | 나머지로 답변 (부분 실패 허용) |
| Gutendex 다운 | Open Library 무료전문으로 폴백 |
| 알라딘 키 오류 | **HTTP 200 + `errorCode`** 를 직접 검사해 빈 배열 |
| 외부 API 지연 | 5초 타임아웃 + 1회 재시도 |
| 도구 루프 지연 | 18초 예산 초과 시 검색 중단하고 답변 마무리 |
| 기록 저장 실패 | `logRef` 가 없으니 평가 버튼을 아예 안 보여줌 |
| 평가 전송 실패 | 예외를 던지지 않고 안내만 (대화가 끊기면 안 됨) |
| localStorage 차단 | 메모리 폴백 + 시크릿 모드 경고 표시 |
| 응답이 비었음 | 진단 문구 표시 (이벤트 수·첫 바이트·경과 시간) |

"조용히 실패하지 않는다"가 원칙입니다. 알라딘이 오류도 200 으로 주는 것을
발견하고 본문을 직접 검사하게 만든 것, 헬스체크에 `warnings` 배열을 신설해
"서비스는 도는데 품질이 떨어진 상태"를 구분한 것이 그 결과입니다.

## 3-4. 도서관의 기준을 따르는 가드레일

주제로 검열하지 않습니다. 성인 문학·폭력·정치를 다루는 문학은 **추천합니다**
도서관이 그렇게 하기 때문입니다. 스위치가 아니라 기본 동작입니다.

대신 예외 없는 절대 차단선을 둡니다.

| 층 | 막는 것 |
|---|---|
| `MINOR_SAFETY` | 미성년 관련 — 예외 없음 |
| `INJECTION` | 프롬프트 인젝션 · 시스템 프롬프트 탈취 |
| `PII` | 개인정보 요구 |
| `HARMFUL` | 실제 위해 |
| 인코딩 우회 | base64 덩어리 · 제어문자 |
| LLM 판정 | 규칙으로 애매한 것만 2차 |

정책 모듈은 `/api/guard` 로 단독 호출도 가능해서 외부 벤치마크(GuardBench)와
연동해 오탐률을 측정할 수 있습니다.

## 3-5. 사용자 데이터를 서버에 두지 않음

읽을 목록은 **브라우저에만** 저장됩니다. 서버 호출이 0 입니다.

| 결과 | |
|---|---|
| 서버 비용 | 0원 |
| 로그인 | 불필요 |
| 개인정보 문의 | "브라우저에만 저장되며 서버로 전송되지 않습니다" |
| 백엔드 장애 | 읽을 목록은 그대로 열림 |
| 한계 | 브라우저를 바꾸면 사라짐 (의도된 트레이드오프) |

권당 8KB 원본을 **280바이트로 축소**해 저장하고, 상한 200권을 넘으면
**거부합니다** — 오래된 항목을 몰래 지우지 않습니다.

## 3-6. 측정 가능한 서비스

답변 평가가 **원래 대화 기록 항목에 속성으로 붙습니다.** 별도 테이블이 없습니다.

```
pk = LOG#2026-09-01
sk = 2026-09-01T07:56:00.725Z#a1b2c3d4
     질문 · 답변 · 평가 · feedbackAt
```

콘솔에서 한 줄만 봐도 "어떤 질문에 어떻게 답했고 사용자가 어떻게 느꼈는지"를
알 수 있습니다. 운영자는 `아쉬움` 이 붙은 질문만 뽑아 원인별로 대응합니다 —
국내서 부족이면 알라딘 키, 무드 추천이 엉뚱하면 Hardcover 토큰, 말투 문제면 프롬프트.

`logRef` 는 브라우저를 거쳐 돌아오므로 조작 가능합니다. 그래서 길이 상한 80자와
엄격한 정규식으로 `LOG#` 파티션만 허용하고, `SESSION#`·`CACHE#`·`RL#` 조작을
차단합니다. 이 검증만 13건의 테스트로 고정해 두었습니다.

## 3-7. 배포와 검증이 코드로 남아 있음

콘솔 클릭으로 만든 것을 나중에 재현할 수 없다는 문제를 피했습니다.

- 인프라 스크립트 **20개** — 전부 재실행 안전(idempotent)
- `update.sh` 하나로 갱신 배포 (순서 실수 방지)
- `doctor.sh` — 진단 + 자동 수정
- `verify.sh` — 배포 후 실제 사이트를 호출해 채팅·평가·보안·레이트리밋 확인
- `destroy.sh` — 정리

자동 검증 **166건** 중 152건은 네트워크를 쓰지 않아 결과가 흔들리지 않습니다.
과거에 실제로 났던 사고들이 전부 테스트로 고정되어 있습니다 —
흰 화면 사고, 핸들러 되돌림, 환경변수 소실, 504 타임아웃, 저자 표기로 인한 중복 카드.
