# 1부. AWS 기능과 적용

## 전체 구성

```
브라우저
  ↓ HTTPS
CloudFront ──┬─ /*      → S3        (React 정적 사이트, 버킷 완전 비공개)
   + WAF     └─ /api/*  → Lambda    (API Gateway HTTP API 경유)
                            ├ Bedrock       모델 호출
                            ├ 도서 API 6곳   외부 검증
                            ├ DynamoDB      세션·캐시·레이트리밋·기록
                            └ SSM           API 키
```

## 서비스별 활용

| 서비스 | 무엇에 썼나 | 핵심 설정 |
|---|---|---|
| **CloudFront** | 유일한 공개 진입점 | 오리진 2개 · OAC SigV4 · `/api/*`만 Lambda로 · SSE 때문에 압축 끔 |
| **Lambda** | 애플리케이션 전체 | 핸들러 2개(스트리밍/버퍼) · Node 22 · **예약 동시성 10** |
| **API Gateway** | HTTP API 프록시 | `ANY /api/{proxy+}` · 통합 타임아웃 **30초(증액 불가)** · 초당 10 스로틀 |
| **DynamoDB** | 단일 테이블 4용도 | `PAY_PER_REQUEST` · TTL · **원자적 `ADD`** |
| **Bedrock** | LLM 호출 | `ConverseStream`(도구 사용) · Claude Sonnet 4.6 · maxTokens 3072 |
| **SSM Parameter Store** | API 키 5개 | SecureString · **무료**(Secrets Manager는 월 $0.40/개) · 5분 캐시 |
| **S3** | 정적 호스팅 | 공개 차단 4종 전부 true · OAC로만 접근 |
| **WAF** | IP 기반 차단 | 전체 5분당 300회 / `/api/chat` 100회 → Block |
| **CloudWatch + SNS** | 알람 4종 | 오류·스로틀·60초 초과·시간당 출력토큰 20만 |
| **Budgets** | 비용 상한 | 전체 $100 / Bedrock $50 (50%·80%·예측 100%) |
| **IAM** | 최소 권한 | 테이블·파라미터 경로 한정 · KMS는 SSM 경유만 |
| **CloudShell** | 배포 실행 | 콘솔 로그인이 MFA를 만족 (FIDO 키만 등록돼 로컬 CLI 불가) |

## DynamoDB 단일 테이블 — `pk` 접두사로 4용도

| 접두사 | 용도 | TTL |
|---|---|---|
| `SESSION#` | 대화 이력 | 24시간 |
| `LOG#` | 검토용 기록 | 90일 |
| `CACHE#` | 외부 API 응답 | 6시간 |
| `RL#` / `RLOAI#` | 레이트리밋 카운터 | 120초 / 25시간 |

테이블을 4개 만들면 관리 지점도 4배가 됩니다. 접두사로 나누면 하나로 끝납니다.
레이트리밋의 `ADD`는 원자적이라 동시 요청에도 카운트가 정확합니다.

## 비용 방어 4층

로그인 없는 공개 서비스 + Bedrock 호출이라 여기가 가장 중요합니다.

```
1층  앱 레이트리밋 (DynamoDB)   분당 10 / 하루 150
2층  WAF rate-based            5분당 300 (채팅 100)
3층  Lambda 예약 동시성          10
4층  AWS Budgets               $100 / Bedrock $50
```

## 인증 — 왜 IAM이 아닌가

함수 URL을 `AuthType=AWS_IAM` + OAC로 두려 했으나 AWS 제약에 막혔습니다.
본문 있는 POST는 **브라우저가** 본문 SHA-256을 서명해야 하는데 공개 웹앱에서는 불가능합니다.

→ `AuthType=NONE` + **CloudFront가 오리진으로만 주입하는 `x-origin-secret` 헤더**.
   상수 시간 비교, SSM SecureString 보관. 브라우저에 노출되지 않습니다.

# 2부. 책 추천 서비스 구현

## 일반 챗봇과의 차이

```
일반 챗봇   입력 → 모델 → 출력                       모델이 아는 것을 말한다
BookBot     입력 → 검문 → 모델 ↔ 외부 DB → 검증 → 출력  외부에서 확인된 것만 말한다
```

LLM은 **"왜 이 책인지" 설명만** 합니다. 제목·저자·표지·평점·ISBN은 전부 API에서 옵니다.

## 요청 흐름

```
1. 문지기      오리진 비밀 · 2,000자 · 세션ID · 레이트리밋
2. 정책 검사   정규식 27개(미성년·인젝션·PII) → 걸리면 Bedrock 0회, 0.2초 종료
               통과하면 Bedrock으로 의도 분류 (BOOK / SERVICE / ATTACK)
3. 도구 루프   Bedrock 호출 → toolUse 오면 도구 실행 → 결과 되돌려주기 (최대 4회)
4. 검증        API 6곳 조회 → 중복 제거 → 제목·저자 대조
5. 카드 선별   답변이 언급한 책만 카드로, 부족하면 채움
6. 출력        SSE 이벤트 + DynamoDB 저장
```

## 검증 로직 — 이 서비스의 핵심

모델이 "《종의 기원》 정유정"을 떠올리면 API로 대조합니다.

```
제목 유사도 ≥ 0.7   AND   저자 유사도 ≥ 0.5   →  통과
```

| 임계값 | 근거 |
|---|---|
| 제목 0.7 | 0.62였을 때 「종의 기원」 요청에 「종의 기원과 진화론」이 0.64로 통과했습니다 |
| 저자 0.5 | 「1984」는 조지 오웰 원작 외에 해설서·만화판이 많습니다. 저자가 다르면 **다른 책**입니다 |

대조 전 정규화: NFKD → 발음기호 제거 → NFC, 장식 문자(`《》**「」`) 제거,
조사 처리(「가와바타」가 조사 `가`로 잘리던 버그), 권차 제거(「혼불 1」→「혼불」).

**검증 실패한 책은 답변에서 언급 금지.** 환각을 프롬프트로 부탁하는 게 아니라
구조로 막습니다.

## 소스 6곳 · 언어별 라우팅

```
한국어 맥락 → 알라딘 + 국립중앙도서관      (보낼 한국어 검색어가 있을 때만)
영어권      → Google Books + Open Library + Hardcover + Gutendex
0권이면     → Google Books(langRestrict=ko)로 폴백
```

결과 병합: ISBN13 1차 중복 제거 → 제목·저자 유사도 2차 → 필드 병합(표지 채움)
→ 점수 정렬(평점·평점수·연도·장르 적합성) → 장르 불일치 제거

## 도구 5종

| 도구 | 용도 |
|---|---|
| `search_books` | DB 6곳 통합 검색 (기본 14권) |
| `browse_by_subject` | 주제·분위기 탐색 |
| `lookup_books` | 제목·저자로 특정 책 확인 ← **장르 요청에는 이걸 먼저** |
| `find_free_ebooks` | 구텐베르크 무료 전자책 |
| `get_book_detail` | 한 권 상세 |

## 카드 선별

```
검색 18~40권 → 시리즈 접기 → 답변에서 《》 제목 추출 → 언급된 책만 카드
             → 12장까지 채움(문자체계 맞춤) → 답변에 있는데 카드 없으면 재조회
```

한글 제목 책을 추천했으면 채우는 책도 한글로 제한합니다.
그러지 않았을 때 "위로되는 한국 소설" 요청에 캐나다 통계 자료가 카드로 나갔습니다.

## 로딩 중 메시지

API Gateway는 응답 스트리밍을 지원하지 않아 진행 이벤트가 **마지막에 한꺼번에** 옵니다.
기다리는 동안 알 수 있는 정보가 없습니다.

**설계 원칙 — 모르는 것을 아는 척하지 않는다.** "Google Books 검색 중"은 거짓입니다.
확실한 것만 씁니다.

```
경과 시간   Date.now() 기준 실측 (3초 뒤부터 표시)
단계 문구   서버 예산 배분에 맞춘 4단계

  0초   준비하고 있어요…
  2초   여러 도서관과 서점을 찾아보고 있어요…
 12초   찾은 책 중에서 골라 정리하고 있어요…
 22초   거의 다 됐어요. 조금만 기다려 주세요.
```

숫자가 추측이 아니라 백엔드 예산과 맞춘 값입니다. **예산을 바꾸면 여기도 고쳐야** 합니다.

## 답변 언어

프롬프트의 "사용자가 쓴 언어로 답하세요"는 실제로 지켜지지 않았습니다.
영어로 세 번 물은 사용자에게 한국어 답변이 나갔습니다.

→ 코드가 **문자체계로** 판정하고(`detectReplyLanguage`), 매 턴 **현재 입력**으로
  다시 봅니다(대화 이력 오염을 끊는 지점). 지시문은 시스템 프롬프트 **맨 끝**에 붙입니다.

